1. PROJECT OVERVIEW
================================================================================
Aarambh Saathi (meaning Starting Companion) is an AI-driven, hyper-local
business advisory and financial structuring assistant for rural micro-entrepreneurs
in India.

It guides a rural user (farmer, tailor, daily labourer, homemaker) through an
18-state conversation funnel:

  1. Collects user profile: name, village, occupation, skills, capital, resources
  2. Recommends Top 3 matching rural businesses via deterministic scoring engine
  3. Shows required machinery and equipment for chosen business
  4. Lists verified machinery suppliers with pricing and contact info
  5. Calculates financial plan: EMI, loan amount, payback period
  6. Matches user with government subsidy schemes (central and state level)
  7. Generates 90-Day Detailed Project Report (DPR) in EN, Hindi, Marathi

4. CHATBOT WORKFLOW - 18-STATE MACHINE
================================================================================

Linear funnel. Each user message advances exactly ONE state.
Sessions are stored in-memory in the SESSIONS dict (chatbot.py).

STATE FLOW:
  PERSONAL_NAME          Bot asks for user name.
  PERSONAL_PLACE         Bot asks for village / location.
  PERSONAL_OCCUPATION    Bot shows occupation chips:
                         Farmer / Tailor / Student / Homemaker /
                         Daily Labourer / Retail Shopkeeper
  BUSINESS_SKILLS        Bot shows 4 skill chips (filtered by occupation).
  BUSINESS_RESOURCES     Bot asks what resources the user owns.
                         (land, cattle, shop, vehicle, tools, etc.)
  BUSINESS_CAPITAL       Bot asks available capital in rupees.
  BUSINESS_INTEREST      Bot shows 3-4 business ideas (by occupation).
  PROFILE_CONFIRMATION   Bot summarizes the profile. User confirms.
  RECOMMENDATION         Bot shows Top 3 matching businesses with scores,
                         why_matches list, investment range, risk summary.
  BUSINESS_SELECTION     User selects one business to pursue.
  FEASIBILITY            Bot shows hyper-local feasibility: market opportunity,
                         competition level, risk, positive and caution factors.
  EQUIPMENT_SUPPLIER     Bot shows:
                           a) Required machinery list for chosen business
                           b) Verified supplier per machine (name, location,
                              price range, phone, GST, delivery, warranty)
  SUPPLIER_DONE          Bot asks: proceed to finance? Check schemes?
  FINANCIAL              Bot shows: scheme tier, loan amount, monthly EMI,
                         total repayment, break-even months.
  SCHEME_OPT_IN          Bot asks if user wants to check government schemes.
  SCHEME_PROFILE         Collects gender / social category for eligibility.
  SCHEME_MATCHING        Bot shows matched central + state government schemes
                         with documents required, support type, official links.
  DPR                    Bot generates full 90-Day DPR in session language.
  COMPLETE               Conversation done. Option to restart.

--- 5.2 chatbot.py (1068 lines - Core State Machine + NLU) ---

  GLOBAL CONSTANTS:
    SESSIONS                In-memory: session_id -> {state, profile, language}
    WORKFLOW_STATES         Ordered list of 18 state names
    BIZ_SECTOR_TO_MACHINE_CATEGORIES  keyword -> machine category list
    OCCUPATION_SKILLS_MAP   occupation -> 4 skill quick-reply options
    OCCUPATION_BUSINESS_MAP occupation -> 3-4 business idea options
    KEYWORD_MAP             business keyword -> canonical business name

  FUNCTIONS:
    extract_capital_from_text(text) -> Optional[float]
      Parses: "1 lakh", "50,000", "ek lakh", "pannas hazar", "Rs 1.5L"
      Also handles Devanagari word forms.
      Returns rupee amount as float, or None if not found.

    clean_name_string(raw) -> str
      Strips: "My name is", "I am", "mera naam", "mazhe naav"
      Returns capitalized name.

    clean_location_string(raw) -> str
      Strips: "I live in", "from", "yethe rahto", etc.

    resolve_state_from_location(loc) -> str
      Maps known city names to Indian states. Default: Maharashtra.

    extract_entities_locally(user_msg, current_state) -> Dict
      Rule-based multilingual entity extractor (EN/HI/MR).
      Extracts: name, location, capital, occupation, skills,
                resources, business_interest from free text.

    call_gemini_nlu(user_msg, state, profile, language, history) -> Dict
      Google Gemini flash model for entity extraction fallback.
      Returns JSON dict with extracted profile field values.
      Only activated when GEMINI_API_KEY env var is set.

    get_bot_response(state, profile, language) -> (str, List[str])
      Deterministic template-based bot reply for each state.
      Generated in EN/HI/MR based on language. NO LLM calls.
      Returns (bot_message_text, suggested_quick_replies_list).

    process_chat(request: ChatRequest) -> ChatResponse   [MAIN FUNCTION]
      1. Create or retrieve session from SESSIONS dict
      2. Check business keyword interceptor (DISABLED in early states)
      3. Advance state machine based on current_state + user message
      4. extract_entities_locally() -> merge extracted fields into profile
      5. call_gemini_nlu() as fallback if local extraction is incomplete
      6. get_bot_response() -> bot reply text + quick_reply chips
      7. When state == DPR: generate full trilingual DPR inline (no LLM)
      8. Return ChatResponse with updated_profile, quick_replies, is_profile_ready

  DPR GENERATION (state == DPR) - FULLY DETERMINISTIC:
    Template fill using profile data. No LLM involved.
    Computes: project_cost, loan_amount, monthly_revenue, monthly_profit,
              payback_period_months, machines_list, action_plan M1/M2/M3,
              applicable government scheme name.
    Output in EN/HI/MR based on session language.

--- 5.3 recommendation.py (Business Scoring Engine) ---

  SECTOR_KEYWORD_MAP: 11 sectors -> keyword lists
    DAIRY, GOAT_SHEEP, POULTRY, LIVESTOCK, FISHERIES, BEEKEEPING,
    AGRICULTURE, TEXTILES, FOOD_PROCESSING, MANUFACTURING

  detect_user_target_sector(profile) -> Optional[str]
    Priority 1: business_interest + skills fields
    Priority 2: occupation + experience + resources fields

  detect_business_sector(business_dict) -> str
    Categorizes using category/name/description text.

  score_business(biz_dict, profile) -> BusinessRecommendation
    3-factor weighted scoring (max approx 100 points):

    Skill Match (max 70 pts):
      - Overlap: user skills vs 3 required_skills per business
      - Direct interest name match bonus: +20 pts
      - Sector alignment boost: +15 to +25 pts
      - Cross-sector keyword matching (livestock mgmt <-> animal care)
      - Hard filter: -50 pts for unrelated manufacturing + livestock profile

    Experience (max 15 pts):
      5yr/experienced=15, some/basic=12.5, default=10

    Capital and Resource Match (max 15 pts):
      >= recommended_investment: 15 pts
      >= minimum_investment: 13 pts
      >= 10% of minimum (margin money eligibility): 11.5 pts
      not stated: 12 pts

  get_recommendations(profile, top_n=3) -> RecommendationResponse
    Scores all 90 businesses. Sorts descending by total_score.
    Returns top 3 with score >= 50.
    Fallback: top 3 regardless of score if none reach threshold.

--- 5.4 finance.py (EMI and Financial Structuring Engine) ---

  SCHEME TIERS (National Micro-Enterprise Lending Framework - SIH26091):
    Micro Finance:  Cost <= Rs 1,40,000  | Rate 6.5% p.a. | 3yr | Morat 3mo
    Term Loan:      Cost <= Rs 50,00,000 | Rate 8.0% p.a. | 7yr | Morat 6mo
    Commercial:     Cost > Rs 50,00,000  | Rate 12% p.a.  | 5yr | Morat 3mo
    Max financing cap: 90% of project cost in all tiers.

  validate_financial_inputs(...) -> List[str]
    Validates: project_cost, own_contribution, revenue, expenses, rates.

  calculate_reducing_balance_emi(principal, annual_rate, tenure_months) -> float
    EMI = P * r * (1+r)^n / ((1+r)^n - 1)  [standard reducing balance]

  calculate_financial_plan(inputs: FinancialInput) -> FinancialPlan
    1. Detect tier from project_cost
    2. own_contribution = max(10% of cost, user-provided amount)
    3. required_loan = project_cost - own_contribution (capped at tier max)
    4. monthly_emi = calculate_reducing_balance_emi()
    5. total_repayment, interest_payable computed
    6. monthly_profit = revenue - operating_expenses - EMI
    7. break_even_months = own_contribution / monthly_profit
    Returns: complete FinancialPlan object.

--- 5.5 feasibility.py ---

  evaluate_hyper_local_feasibility(business_id, profile) -> FeasibilityResponse
    Rule-based. 100% deterministic. No LLM.
    Evaluates: market_opportunity, competition_level, resource_availability,
               risk_level, positive_factors, caution_factors.
    Returns feasibility_score 0-100 + factor lists.

--- 5.6 schemes.py (Government Scheme Matcher) ---

  SECTOR_ALIASES: 9 sector groups -> keyword lists.
    Agriculture and Allied, Manufacturing and Processing, Food Processing,
    Services and Textiles, Dairy and Livestock, Fisheries and Aquaculture,
    Clean Energy and Renewable, Women and Rural Livelihoods,
    Artisans and Traditional Crafts.

  match_government_schemes(profile, business_id, category, project_cost)
    -> List[MatchedScheme]
    Per scheme scoring:
      +40: exact business_id in scheme eligible_ids list
      +25: category/sector match via SECTOR_ALIASES
      +20: user interest keyword match
      +15: user resource match (user has cattle -> dairy scheme matched)
      +10: state-level scheme, user is in that state
      +5:  gender-specific scheme, user is female
      Skip: state scheme does not match user state
    Returns top 5 highest-scoring schemes.

--- 5.7 supplier.py (Machinery and Supplier Engine) ---

  BUSINESS_EQUIPMENT_MAP: keyword -> list of machine IDs
    e.g. "dairy" -> ["M001","M002","M003","M004","M005",...]
    Covers: spice, dairy, poultry, mushroom, flour, pickle, bakery,
    tailoring, beekeeping, goat, fish, bamboo, mobile repair, etc.

  load_all_machines() -> List[Dict]   Reads data/machines.json
  load_all_suppliers() -> List[Dict]  Reads data/suppliers.json

  get_required_machines(business_name, business_scale) -> List[Dict]
    business_name keyword -> machine IDs -> machine details with price range.

  search_suppliers(machine_id, location, budget, capacity) -> List[Dict]
    Queries all ACTIVE_SOURCES.
    Deterministic ranking: location proximity > budget fit > source reliability.
    Returns: name, location, phone, price, GST, delivery_days, warranty, website.

  get_supplier_recommendations(biz_name, scale, location, budget) -> Dict
    Full pipeline: get_required_machines + search_suppliers per machine.
    Returns {machines: [...], suppliers_by_machine: {...}}

    runAnalysisPipeline(profile, preferredBusinessId)

        1. getRecommendations(profile)

      5. Triggers voice output if in voice mode

    handleSelectBusiness(bizId)
      Updates selectedBusinessId. Re-runs feasibility and scheme matching.

    handleOpenReport()
      Calls generateReport() -> POST /api/report. Opens ReportModal.

11. AI USAGE - GEMINI vs. DETERMINISTIC
================================================================================

GEMINI IS USED FOR:
  chatbot.py -> call_gemini_nlu() function only
  NLU fallback: extracts name/location/skills from free-form chat text
  Model: gemini-1.5-flash
  Prompt: structured JSON extraction from user message
  Gracefully disabled and skipped when GEMINI_API_KEY is not set

ALL CRITICAL OUTPUTS ARE DETERMINISTIC (NO LLM):
  Business recommendation scoring  (recommendation.py)
  Financial EMI and loan plan       (finance.py)
  Feasibility scoring               (feasibility.py)
  Government scheme matching        (schemes.py)
  Machinery and supplier matching   (supplier.py)
  DPR report generation             (chatbot.py DPR state)
  All chatbot bot message replies   (get_bot_response())

WHY DETERMINISTIC APPROACH:
  - No hallucination risk in financial advice to rural users
  - System works fully offline without GEMINI_API_KEY
  - All outputs are reproducible, auditable, and explainable
  - Financial accuracy is critical for real loan and scheme applications

15. KEY DESIGN DECISIONS AND PRINCIPLES
================================================================================

1. DETERMINISTIC FIRST
   All critical outputs (scores, EMI, scheme matches, DPR) are fully deterministic.
   Gemini used only as NLU fallback for free-text entity extraction.
   Prevents hallucinations in financial advice given to rural users.

2. OFFLINE RESILIENCE
   All business, scheme, machine, and supplier data stored locally in JSON.
   System works fully without any external API calls.
   Gemini gracefully degrades if GEMINI_API_KEY is missing.

3. RURAL ACCESSIBILITY
   Voice input and output in Hindi, Marathi, and English.
   Large tap targets and simple UI for low-digital-literacy users.
   Occupation-specific quick-reply chips eliminate the need to type.
   Capital input handles: "1 lakh", "50 hazar", "ek lakh", "Rs 50,000" etc.

4. FRONTEND-ONLY RBAC
   Admin RBAC via localStorage (no backend auth).
   Suitable for hackathon and MVP stage.
   Can be upgraded to JWT-based backend auth in production.

5. PLUGGABLE SUPPLIER SOURCES (Adapter Pattern)
   ACTIVE_SOURCES list in supplier.py.
   New supplier data source: add adapter class to backend/supplier_sources/.
   No changes needed in core supplier.py logic.

6. STATE MACHINE SAFETY
   Business keyword interceptor is DISABLED during early profile collection
   states (PERSONAL_NAME through BUSINESS_INTEREST).
   Prevents occupation answers like "Farmer" from incorrectly jumping
   to the supplier lookup state mid-profile-collection.

7. CHAT SCROLL ISOLATION
   chatContainerRef.scrollTop = scrollHeight for internal chat scroll only.
   scrollIntoView() is NEVER called from the message-send handler.
   Page/window position is unchanged when user sends chat messages.
   Journey navigation (steps 2/3/4) uses scrollIntoView only on
   explicit user click via handleJourneyStepClick().
